The eight vitals

Eight checks on your token system

Each check is graded on its own, against evidence pulled from your repository. There is no single overall score, because averaging these would hide the one thing you need to see. If your system has no dark mode, that check is marked not applicable rather than counted against you. And if a check could not run at all, it says blocked instead of quietly passing.

Pass

Tier integrity

All three tiers are intact. Every one of your 148 component tokens resolves through a semantic alias, so nothing reaches straight for a raw palette value.

Fail

Lineage

Where each token comes from

A chain runs primitive definition to semantic alias to custom-property projection to the components that use it. The chain is what separates a deliberate alias from a duplicate definition: two names for one value with a link between them is the system working, and two names without one is drift. A dashed step is a link this run could not trace.

$teal-600→ --brand→ --color-brand→ 11 components
$font-size-3→ --text-sm→ --typeset-body-sm→ 28 components
$font-size-4→ --text-base→ no projection traced→ 9 components
#0F8A83→ no semantic alias→ no projection→ 2 components
The fourth chain is the duplicate this catches. #0F8A83 is defined a second time with nothing linking it to --brand, which already holds that value. The first three chains are alias layers working as designed, and grading them the same way would report a healthy system as drift.
